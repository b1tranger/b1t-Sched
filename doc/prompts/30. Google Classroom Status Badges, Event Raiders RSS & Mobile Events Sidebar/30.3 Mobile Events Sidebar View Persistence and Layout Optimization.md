### AI Thought

1. **Analyze User Requirements**:
   - **View State Persistence in `localStorage`**:
     - When users switch the mobile events sidebar view between b1t-Sched internal events (`'internal'`) and UITS Event Raiders (`'raiders'`), persist this state in `localStorage` (`b1t_events_sidebar_view`).
     - On app load/initialization, restore the user's last selected view state so the preference is preserved across page refreshes and browser sessions.
   - **Two-Segment Layout for `<div class="event-content">`**:
     - In both internal and Raider event cards, currently `<div class="event-content">` sits completely to the right of `<div class="event-date">`.
     - When details, badges, and descriptions expand vertically, it leaves a large empty blank block directly underneath the date badge (`.event-date`).
     - Restructure `.event-content` into two segments:
       1. `<div class="event-header">` placed directly beside `<div class="event-date">` (Row 1).
       2. `<div class="event-details">` placed directly below `<div class="event-date">` and spanning full card width (`100%`) (Row 2), eliminating wasted space.
   - **Compact Header Padding for `<div class="events-sidebar-header">`**:
     - Reduce top and bottom padding from `var(--spacing-lg)` (18px) to `var(--spacing-sm) var(--spacing-lg)` (~6-8px vertical padding) to grant more vertical height for event content.

2. **Implement JavaScript & State Management**:
   - In `js/app.js`:
     - Initialize `mobileEventsActiveView: localStorage.getItem('b1t_events_sidebar_view') || 'internal'`.
     - In `setupEventsSidebarListeners()`:
       - Read `localStorage.getItem('b1t_events_sidebar_view')` on startup and call `UI.switchMobileEventsView(this.mobileEventsActiveView)`.
       - On `#events-view-switch-btn` click: toggle view and persist to `localStorage.setItem('b1t_events_sidebar_view', this.mobileEventsActiveView)`.
   - In `js/ui.js`:
     - In `switchMobileEventsView(targetView)`: persist `targetView` to `localStorage.setItem('b1t_events_sidebar_view', targetView)`.
     - In `renderEvents(events)`: wrap the description in `<div class="event-details">` so `<div class="event-content">` has `<div class="event-header">` and `<div class="event-details">`.
     - In `renderRaiderEvents(events)`: wrap badges, contest segments summary, description toggle, and portal link in `<div class="event-details">`.

3. **Implement CSS Grid Layout**:
   - In `css/components.css`:
     - Set `.event-card` to `display: grid; grid-template-columns: auto 1fr auto; align-items: start; gap: var(--spacing-xs) var(--spacing-md);`.
     - Set `.event-date` to `grid-column: 1; grid-row: 1;`.
     - Set `.event-content` to `display: contents;`.
     - Set `.event-header` to `grid-column: 2; grid-row: 1; align-self: center; margin-bottom: 0; min-width: 0;`.
     - Set `.event-actions` to `grid-column: 3; grid-row: 1; align-self: start;`.
     - Set `.event-details` to `grid-column: 1 / -1; grid-row: 2; width: 100%; min-width: 0; display: flex; flex-direction: column;`.
   - In `css/dashboard.css`:
     - Set `.events-sidebar-header { padding: var(--spacing-sm) var(--spacing-lg); }`.
     - Set `.raider-card` to `display: grid; grid-template-columns: auto 1fr;` with `.event-content { display: contents; }` and `.event-details { grid-column: 1 / -1; grid-row: 2; width: 100%; min-width: 0; display: flex; flex-direction: column; }`.
     - Optimized compact padding for `.events-container-mobile .event-card` and `.raider-events-container-mobile .event-card`.
