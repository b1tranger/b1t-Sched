# Walkthrough - Firebase Task ID in Show More & Editable Old Tasks

Integrated Firestore task IDs into the expandable "Show more" section of Pending Tasks cards, enabled direct task editing from the Old Tasks modal, and ensured that extending an old task's deadline immediately restores it to Pending Tasks.

## Changes Made

### 1. Pending Tasks "Show more" Firebase Task ID Display
- [css/components.css](file:///d:/GitHub/[oU1TS]/b1t-Sched/css/components.css):
  - Updated the description expand selector from `.task-description-text.expanded+.task-added-by-hidden` to general sibling combinator `.task-description-text.expanded ~ .task-added-by-hidden` so both "Added by" and "Task ID" reveal smoothly upon expansion.
  - Added `.task-id-info` and `.task-id-code` classes with monospace styling, subtle background pill styling, and `user-select: all` for effortless one-click copying.
- [js/ui.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/ui.js):
  - Updated `renderTaskCard()` to inject `<p class="task-id-info task-added-by-hidden"><span class="task-id-label">Task ID:</span> <code class="task-id-code">${task.id}</code></p>` into the description wrapper.

### 2. Role-Based Old Tasks Direct Editing & Seamless Return to Pending Tasks
- [js/ui.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/ui.js):
  - Updated `renderOldTasks(tasks, isAdmin, currentUserId)` to evaluate edit permissions (`isAdmin || (currentUserId && task.addedBy === currentUserId)`) and render `.old-task-actions` with `.task-edit-btn.old-task-edit-btn`.
- [css/dashboard.css](file:///d:/GitHub/[oU1TS]/b1t-Sched/css/dashboard.css):
  - Added layout and hover styling for `.old-task-actions` and `.old-task-actions .task-edit-btn`.
- [js/app.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/app.js):
  - Updated `oldTasksContainer` click delegation to intercept clicks on `.old-task-edit-btn` and open the Edit Task modal without triggering the item details modal.
  - Updated `openEditTaskModal(taskId)` to search across both `this.currentTasks` and `this.oldTasks`.
  - Updated `handleEditTask()` so that updating a task refreshes `loadDashboardData()`, and if `this.oldTasks` was loaded or the Old Tasks modal is open, re-fetches `DB.getOldTasks` to instantly update the Old Tasks view. If the deadline was moved to a future date or removed, `loadDashboardData()` automatically displays the task in "Pending Tasks".
  - Updated `openOldTasksModal()` to pass `this.isAdmin` and `Auth.getUserId()` to `UI.renderOldTasks()`.
- [js/db.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/db.js):
  - Hardened `DB.getOldTasks()` to gracefully handle Faculty tasks where `semester` and `section` are `null`.

### Manual Workflow Verification Points
1. **Pending Tasks "Show more" Toggle**:
   - In default collapsed state: Task ID is hidden.
   - When clicking **Show more**: Description expands and displays creator details + `Task ID: <firebaseId>`.
   - Clicking on the Task ID selects the entire ID string instantly due to `user-select: all`.
   - Clicking **Show less**: Description and metadata cleanly collapse.
2. **Old Tasks Editing & Reappearance**:
   - Opening Old Tasks modal displays an edit icon on tasks created by the current user (or all tasks if Admin).
   - Clicking the edit icon opens the Edit Task modal pre-filled with the old task data.
   - Changing the deadline to a future date (or "No official Time limit") and submitting saves the task in Firestore, removes it from Old Tasks, and places it into "Pending Tasks".
