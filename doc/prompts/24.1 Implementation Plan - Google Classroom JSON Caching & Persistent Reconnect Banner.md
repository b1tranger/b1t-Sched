# Implementation Plan - Google Classroom JSON Caching & Persistent Reconnect Banner

This plan addresses client-side Google Classroom data persistence via a structured JSON template cache, and implements a persistent bottom banner and "Reconnect Classroom" button when displaying cached content after session expiration.

## Storage Comparison & Recommendation

The prompt mentions generating a user-specific template `.json` file from Google Classroom data and storing it in `sessionStorage`.

| Storage Type | Lifetime | Pros | Cons |
| :--- | :--- | :--- | :--- |
| **`sessionStorage`** | Cleared when browser tab/window is closed | Isolated to active session | **Lost on tab closure or browser restart**, requiring user to sign in again every time they open the site |
| **`localStorage`** *(Recommended)* | Persists until explicitly cleared | Retained across tab closures & browser restarts; works offline | Limited to ~5MB (more than sufficient for text/JSON classroom data) |
| **`CacheStorage` (Cache API)** | Persists until explicitly cleared | Already integrated via `CacheManager` | Stores responses/blobs |

> [!TIP]
> **Recommended Approach**: Generate a clean JSON data structure (`classroom_cached_json`) containing all user courses, assignments, notices, and materials with a timestamp, and store it in `localStorage` (with a `sessionStorage` fallback/mirror). This guarantees that even if a user closes their browser and opens `b1t-Sched` hours later after token expiry, their cached Classroom data remains instantly accessible.
