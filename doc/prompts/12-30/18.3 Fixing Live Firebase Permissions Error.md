### Root Cause Analysis

#### 1. Why `Missing or insufficient permissions` occurs on the Live Website
- In `firestore.rules`, all data reads (`users`, `metadata`, `tasks`, `cr_notices`, `notes`, etc.) require an authenticated user (`request.auth != null`).
- When running on your live domain, Firebase Authentication fails to authorize or pass the auth token to Firestore if:
  - **The live domain is missing from Firebase's Authorized Domains list** (most common cause), OR
  - **Google Cloud API Key HTTP Referrer restrictions block the live site origin** (causing the `Failed to load resource: 404` error seen in your console), OR
  - **Firestore security rules in Firebase Cloud Console are outdated** and have not been deployed from `firestore.rules`.
- Because Firebase Auth is unauthenticated on the live origin, `request.auth` remains `null`. Firestore security rules reject all queries (`getUserProfile`, `getUserRoles`, `getDepartments`, `getSemesters`, `loadNote`) with `FirebaseError: Missing or insufficient permissions`.

#### 2. Why it redirected to `#/set-details` instead of `#/dashboard`
- Upon login/load, [app.js](file:///c:/Users/.../Documents/GitHub/%5BoU1TS%5D/b1t-Sched/js/app.js#L1084) called `DB.getUserProfile()`.
- Because `getUserProfile()` failed with `Missing or insufficient permissions`, `profileData` returned `null` (since `localStorage` cache was empty on the live domain).
- The application code previously treated `!profileData` as a "first-time user without a profile", triggering `Router.navigate('set-details')`.
- On the `set-details` view, `getDepartments()` and `getSemesters()` were invoked, which also failed with `Missing or insufficient permissions`.

### Key Code Updates Applied

1. **[db.js](file:///c:/Users/.../Documents/GitHub/%5BoU1TS%5D/b1t-Sched/js/db.js#L30-L36)**:
   - Updated `getUserProfile()` to distinguish between document non-existence (`isNotFound: true`) vs permission/network errors (`isNotFound: false`).

2. **[app.js](file:///c:/Users/.../Documents/GitHub/%5BoU1TS%5D/b1t-Sched/js/app.js#L1192-L1206)**:
   - Updated `handleAuthenticatedUser()` to only redirect to `#/set-details` when `profileResult.isNotFound` is true (actual first-time users).
   - If a Firebase permission error occurs, the user is alerted to check Firebase console permissions instead of being stuck in `#/set-details`.

### Step-by-Step Fix Guide for Live Firebase Deployment

#### Step 1: Add Live Domain to Firebase Authorized Domains (Crucial)
1. Open the [Firebase Console](https://console.firebase.google.com/).
2. Select your project: **`b1t-sched`**.
3. Go to **Authentication** > **Settings** > **Authorized domains**.
4. Click **Add domain** and add your live site domain (e.g. `ou1ts.github.io`, `b1tranger.github.io`, or your custom domain).

#### Step 2: Check Google Cloud API Key HTTP Referrer Restrictions
1. Open [Google Cloud Credentials Console](https://console.cloud.google.com/apis/credentials).
2. Select project **`b1t-sched`**.
3. Click on your **Web Client / Firebase API Key**.
4. Under **Website restrictions**, ensure your live site URL (e.g., `https://ou1ts.github.io/*`) is listed alongside `localhost`.
5. Save changes.

#### Step 3: Deploy Firestore Security Rules to Production
Deploy the current [firestore.rules](file:///c:/Users/.../Documents/GitHub/%5BoU1TS%5D/b1t-Sched/firestore.rules) to your live Firebase project by running:
```bash
npx firebase-tools deploy --only firestore:rules
```

#### Step 4: Re-inject Environment Variables & Deploy Production Build
Make sure `node inject-env.js` runs prior to deploying the website to production so `js/firebase-config.js` carries the updated API key and credentials.
