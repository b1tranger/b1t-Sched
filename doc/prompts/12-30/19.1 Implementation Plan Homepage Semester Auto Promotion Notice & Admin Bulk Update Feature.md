## Technical Explanation (Firebase Auto-Updating vs Admin Feature)

### Is Auto-Updating Semester Values Possible with Firebase?
**Yes, in two primary ways:**

1. **Client-Side Auto-Promotion on User Login (Already Active in Codebase)**
   - Inside `js/app.js`, `checkAndUpdateUserSemester(userId, profileData)` evaluates the user's `lastSemesterCycle` against `Utils.getSemesterCycle()` (`YYYY-01` for Jan-Jun, `YYYY-07` for Jul-Dec).
   - When a student logs in during a new cycle, their semester is automatically incremented in Firestore (`1st` $\rightarrow$ `2nd`, etc.), and a modal notifies them of their new semester.
   - *Limitation:* Only updates active users when they log in. Inactive or infrequent users remain in their old semester until their next sign-in.

2. **Server-Side Scheduled Cloud Function (Fully Automated)**
   - Using Firebase Cloud Functions with Cloud Pub/Sub scheduled triggers (e.g., `pubsub.schedule('0 0 1 1,7 *')`), a server function can automatically query all user documents in Firestore and increment their semesters on July 1st and January 1st automatically without any user or admin action.

3. **Why the Admin Bulk Update Feature is Recommended & Useful**
   - Provides immediate consistency across all database records before students log in (e.g., for shared task distributions, section filters, or global stats).
   - Gives admins manual control, transparency, and instant feedback via a confirmation popup and dedicated button in User Management.
