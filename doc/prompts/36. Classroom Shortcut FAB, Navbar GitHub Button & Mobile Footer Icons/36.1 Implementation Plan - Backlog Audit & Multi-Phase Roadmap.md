## 2. Phase A — Bug Fixes & Quick Wins (Code & Styling)

### Item #3: Web App Status Bar Is Green
- **Root Cause**: [index.html](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/index.html#L15) sets `<meta name="theme-color" content="#4CAF50">` (green), overriding the maroon `#660000` theme color in [manifest.json](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/manifest.json#L8).
- **Planned Changes**:
  - Update `<meta name="theme-color" content="#660000">` in `index.html`.
  - Synchronize `meta[name="theme-color"]` dynamically in `js/core/app.js` / `js/features/profile.js` when switching between Light (`#660000`), Dark (`#262626`), and Gray (`#0b0a10`) themes, and align `defaultConfig.theme_color` in `js/pwa/manifest-generator.js`.

### Items #7 & #8: App Icon Not Appearing in Desktop Web App
- **Root Cause**: [manifest.json](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/manifest.json#L10-L22) only provides `"/b1t-sched.webp"` (`type: "image/webp"`), which desktop Chromium/Edge/Windows PWA installers often fail to convert into desktop/taskbar icons; meanwhile, [manifest-generator.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/pwa/manifest-generator.js#L18-L29) references nonexistent `/images/icon-192x192.png` and `/images/icon-512x512.png`.
- **Planned Changes**:
  - Generate standard PNG icons (`images/icon-192x192.png`, `images/icon-512x512.png`, plus `apple-touch-icon.png` 180×180) from `b1t-sched.webp` / `Social-Preview.webp`.
  - Register PNG icons in `manifest.json` (`purpose: "any"` and `"maskable"` entries) and add `<link rel="apple-touch-icon" href="/images/icon-192x192.png">` and PNG `<link rel="icon">` tags in `index.html`, caching them in `sw.js`.

### Item #19 (Sub-item 3): Homescreen Back Button Returns to Logged-Out Login Screen
- **Root Cause**: [routing.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/core/routing.js#L30-L46) has no authentication guard inside `handleRoute()`, and login navigation uses `window.location.hash = '#/dashboard'` (leaving `''` login route in browser history). Pressing Back from `#/dashboard` opens `#login-view`.
- **Planned Changes**:
  - Add an auth guard in `Router.handleRoute()`: if user is authenticated with a completed profile and navigates to `''` (login) or `#/set-details` (when profile already exists), redirect via `history.replaceState` to `#/dashboard`.
  - When logging in (`App.handleAuthenticatedUser`), replace the login history entry (`history.replaceState(null, '', '#/dashboard')`) and handle `popstate` cleanly so pressing Back on the home screen stays on the dashboard or exits cleanly without showing a logged-out login form.
  - Guard reverse redirects (unauthenticated users trying to navigate forward into `#/dashboard`, `#/profile-settings`, `#/user-management`).

### Item #19 (Sub-item 1): Mobile View Missing Notice Cooldown Updates
- **Root Cause**: In [notice.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/features/notice.js#L240-L249) and [index.html](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/index.html#L868), `#refresh-notices-btn-mobile` is hidden until `renderAllNotices()` runs, shows no live cooldown timer state on the button itself, and `UI.showToast` / error banners can be missed behind the mobile notice drawer (`z-index: var(--z-modal)`).
- **Planned Changes**:
  - Add a shared cooldown countdown ticker (`startRefreshCooldownTimer()`) in `NoticeViewer` that disables both `#refresh-notices-btn-mobile` and `#refresh-notices-btn-desktop` during the 60s window and renders remaining seconds directly on the button (`Wait 45s`) plus an inline status badge inside both desktop and mobile notice panels.
  - Ensure `#toast-container` sits above sidebars/modals (`z-index > 12000`) so cooldown toasts are visible on mobile.

### Item #16 (Sub-item 1): 1-Line Caption Truncation in Classroom Window/Sidebar
- **Root Cause**: [css/classroom.css](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/css/classroom.css#L573-L581) applies `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;` to `.item-snippet`.
- **Planned Changes**:
  - Replace single-line `white-space: nowrap` on `.item-snippet` with multi-line wrapping (`white-space: normal; display: -webkit-box; -webkit-line-clamp: 3; -webkit-box-orient: vertical;`) when collapsed and full unconstrained display when `.classroom-item.expanded` is active.

### Item #6 (Sub-item 3): Timeline View Close Button Buggy on Mobile
- **Root Cause**: [css/timeline.css](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/css/timeline.css#L1-L8) shifts `#close-timeline-modal:hover` via `padding: 0 5px 2px 5px; margin-right: -5px;`, causing touch-tap jitter/misalignment on mobile alongside `document.body.style.zoom` interactions in `timeline-ui.js`.
- **Planned Changes**:
  - Remove layout-shifting `padding`/`margin-right` hover rules on `#close-timeline-modal` and enforce a fixed `36px × 36px` (desktop) / `40px × 40px` (mobile) touch target with centered icon alignment and proper `flex-shrink: 0` in `.modal-header`.

### Item #6 (Sub-item 2): Note Link Download Only Opens in New Tab
- **Root Cause**: [notes.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/features/notes.js#L181-L215) and [utils.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/core/utils.js#L216-L221) rely on `<a href="..." download>`, which browsers ignore for cross-origin hosts (`files.catbox.moe`, `tmpfiles.org`, `file.io`).
- **Planned Changes**:
  - Intercept clicks on uploaded file links inside `#note-preview-content` (and task/note description file links) to attempt a CORS `fetch(url) -> res.blob() -> URL.createObjectURL(blob)` download with extracted filename, gracefully falling back to opening in a new tab + helper banner if the host blocks CORS.

### Items #1 & #15: Mobile Add-Task Screen & Form Submissions Overflow / Zoom
- **Root Cause**: `App.adjustMobileZoom()` in [app.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/core/app.js#L352-L358) sets `document.body.style.zoom = '95%'`, while inputs with `font-size < 16px` trigger iOS Safari auto-zoom on focus, and `#add-task-modal`, `#edit-task-modal`, `#add-event-modal`, `#add-cr-notice-modal` lack strict viewport locking (`100dvh`) and compact spacing for small screens.
- **Planned Changes**:
  - Enforce `font-size: 16px` on form inputs/selects/textareas under `@media (max-width: 768px)` to prevent browser auto-zoom on focus.
  - Lock `#add-task-modal` / `#edit-task-modal` / form modals to `100dvh` full-screen on mobile with `overscroll-behavior: none` on the backdrop and non-scrolling outer container (keeping only internal `.modal-body` scrollable if needed, or tightening form spacing/grid rows so the entire Add Task form fits within one mobile viewport without scrolling).
  - Compact `#add-event-modal`, `#add-cr-notice-modal`, `#signup-form`, and `#set-details-form` padding/margins on `<= 480px` to eliminate horizontal/vertical overflow.

## 3. Phase B — Role, Feature & UX Enhancements

### Item #17: DptCoor Should Be Able to Modify Other Faculty Tasks
- **Current Gap**:
  - [firestore.rules](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/firestore.rules#L88-L99) only permits `isAdmin()` or `resource.data.addedBy == request.auth.uid` for task updates/deletes.
  - [ui.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/core/ui.js#L454-L462) and [app.js](file:///d:/GitHub/%5BoU1TS%5D/b1t-Sched/js/core/app.js#L1011) check `canEdit = isAdmin || task.addedBy === userId`.
- **Planned Changes**:
  - Update `firestore.rules` `/tasks/{taskId}` `update` and `delete` rules to allow `isDptCoor()` when `resource.data.department == getUserDepartment()` and the task is a faculty task (e.g., `resource.data.addedByRole == 'Faculty'` or `resource.data.semester == null`).
  - Update `UI.renderTaskCard()` and `App.openEditTaskModal()` / `App.handleDeleteTask()` so `isDptCoor` (when matching department and faculty task) sees Edit and Delete controls on faculty tasks in their department.

### Item #14 (Sub-items 3 & 4): Notifications on Mobile, CR Notice Notifications & Slow Loading
- **Notifications (`js/notifications/notification-manager.js`, `js/core/firestore-listener-manager.js`, `sw.js`)**:
  - Fix `NotificationManager` check (`navigator.serviceWorker.controller` can be `null` right after SW registration; use `await navigator.serviceWorker.ready` whenever `ServiceWorkerRegistration.showNotification` is available).
  - Verify `FirestoreListenerManager.listenForNewNotices` does not fail silently if a composite index on `cr_notices (department, semester, section, timestamp)` is missing (remove `.orderBy('timestamp', 'desc')` or deploy composite index in `firestore.indexes.json`, matching `cr-notice.js` Department notices).
  - Document OS/PWA limitation: real-time `onSnapshot` only delivers notifications while the app/PWA is open in foreground; true closed-app push requires Firebase Cloud Messaging (FCM) + a Cloud Function trigger.
- **Website Load Performance**:
  - Defer heavy third-party libraries (`html2pdf.js`, `jszip`, `chart.js`) so they lazy-load only when Notes/Export/Timeline are opened rather than blocking initial page load.
  - Preload critical cached dashboard data immediately from `localStorage` before Firebase round-trips finish.

### Item #6 (Sub-item 1): Uni Notice Caching / Admin Refresh Persistence

- **Planned Changes**:
  - Mirror the latest fetched University Notice list in a shared Firestore document (e.g., `metadata/uni_notices`) whenever refreshed so every client loads instantaneously from Firestore/localStorage without cold-start delays on the Vercel serverless backend.

### Items #4 & #9: Desktop Login Window & Screen Resolution Scaling
- **Desktop Login Window (`#4`)**: Refine `#login-view` desktop layout (`.auth-hero-wrapper`, `.auth-card`, `.login-footer-section`) into a clean centered/two-column desktop viewport without excessive vertical scrolling.
