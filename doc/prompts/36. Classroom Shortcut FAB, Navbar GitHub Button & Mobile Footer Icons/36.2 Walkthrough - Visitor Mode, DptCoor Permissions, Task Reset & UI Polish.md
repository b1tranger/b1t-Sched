# Walkthrough - Visitor Mode, DptCoor Permissions, Task Reset & UI Polish

## Overview
This walkthrough covers the execution of the user-approved backlog plan across the application, addressing visitor preview mode with client-side only mock data, Department Coordinator permissions to manage faculty tasks, Admin/CR cleanup of tasks without deadlines along with semester auto-pruning, a 2-minute idle timer for password recovery, mobile notification reliability, university notice Firestore caching, desktop login window styling, and comprehensive documentation organization.

---

## Changes Implemented

### 1. Visitor Mode (Client-Side Static Mock Data)
- **Zero Firebase Dependency**: Created `js/features/visitor-data.js` containing rich mock tasks, events, notices, and profile data (`role: 'Visitor'`).
- **Login View Integration**: Added `<button id="visitor-mode-btn">` on `#login-view` in `index.html`.
- **Top Floating Banner**: Added `#visitor-preview-banner` displaying `"Visitor Mode (Preview)"` with an exit/sign-in action.
- **State & Guarding**: In `js/core/app.js`, implemented `startVisitorMode()` and `exitVisitorMode()`. Guarded `loadDashboardData()`, `handleAddTask()`, `openEditTaskModal()`, `handleDeleteTask()`, and `handleResetTasks()`.
- **Interactive Completions**: In `handleTaskCompletion()`, allowed in-memory checkbox toggling without firing backend writes.
- **Profile Modal**: In `js/features/profile.js`, displayed `"Visitor Guest"` and `"Visitor"` role badges, while disabling save operations.

### 2. Department Coordinator Permissions
- **Security Rules**: In `firestore.rules`, updated `match /tasks/{taskId}` update and delete rules to allow `(isDptCoor() && resource.data.department == getUserDepartment())`.
- **Action Buttons**: In `js/core/ui.js`, updated `renderTasks()`, `renderTaskCard()`, and `renderOldTasks()` to accept `isDptCoor` and `userDepartment`, enabling edit and delete buttons on faculty tasks within the same department.
- **Controllers**: In `js/core/app.js`, updated `openEditTaskModal()` and `handleDeleteTask()` to allow Department Coordinators to modify or delete faculty tasks in their department.

### 3. Semester Tracking & Auto-Completion of No-Deadline Tasks
- **Default Semester Deadline**: In `js/core/utils.js`, added `Utils.getSemesterEnd(date)` and `Utils.getCurrentSemesterInfo(date)`. Tasks created with 'No Deadline' automatically set their default deadline to the end of that semester (Spring: June 30 23:59:59, Fall: December 31 23:59:59) with `isNoDeadline: true`.
- **Auto-Completion (No Auto-Deletion)**: In `js/core/db.js` (`DB.resetOldTasks`), removed all auto-deletion for no-deadline tasks. When a semester has ended (or when requested by Admin/CR during reset), no-deadline tasks are automatically resolved and marked completed (`isCompleted: true, autoCompleted: true`) rather than deleted.
- **Dashboard Auto-Resolution**: In `js/core/app.js` (`loadDashboardData`), any no-deadline tasks whose semester has already ended are automatically resolved in `this.userCompletions` as completed.
- **Task Card UI**: In `js/core/ui.js` (`renderTaskCard`), tasks without explicit deadlines display `Due: End of Semester (Date)` and sort after explicit deadline tasks.

### 4. Forgot Password 2-Minute Inactivity Trigger
- **Inactivity Timer**: In `js/core/app.js`, implemented `startForgotPasswordIdleTimer()` and `clearForgotPasswordIdleTimer()` with a 120-second threshold.
- **Form Activity Reset**: Reset the timer on `login-form` input events, clearing it on login submission or view changes.
- **Failed Attempt Visibility**: Kept immediate visibility on invalid password entry.

### 5. Mobile Notification Service Worker Ready Priority
- **Mobile Constructor Fix**: In `js/notifications/notification-manager.js`, updated `showTaskNotification()`, `showEventNotification()`, and `showNoticeNotification()` to check `'serviceWorker' in navigator` and await `navigator.serviceWorker.ready` directly, resolving `TypeError: Illegal constructor` exceptions thrown by mobile browsers when calling `new Notification(...)`.
- **Browser Support**: Enhanced `isSupported()` to recognize PushManager capabilities.

### 6. University Notices Firestore Metadata Caching
- **Instant Loading**: In `js/features/notice.js`, added pre-fetch checks against Firestore document `metadata/uni_notices`, enabling instant loading on student devices without waiting for backend cold starts.
- **Admin Mirroring**: Whenever an Admin refreshes notices, the top 50 notices are automatically mirrored to `metadata/uni_notices`.

### 7. Desktop Login Window Styling & Resolution Scaling
- **Desktop Card Styling**: In `css/main.css`, wrapped `.auth-card` on desktop screens (`min-width: 992px`) with an elevated container, border, backdrop shadow, and responsive padding.
- **Resolution Scaling**: In `js/core/app.js`, refined `adjustMobileZoom()` to set `--app-scale` dynamically across 360px, 480px, 768px, and desktop displays.

### 8. Documentation Reorganization & References
- **Taxonomy Index**: Created `doc/README.md` cataloging features, setup guides, limitations, and prompt archives.
- **References & Libraries**: In `doc/DOCUMENTATION.md` Section 17, documented inspirations from ClickUp, Google Calendar, GitHub, and analytical bar charts, alongside an exhaustive table of client libraries and a record of the reverted Firebase Storage bucket implementation.

### 9. Version Synchronization

- Synchronized `changes.json` under `v2.53.0 to v2.53.16`.
