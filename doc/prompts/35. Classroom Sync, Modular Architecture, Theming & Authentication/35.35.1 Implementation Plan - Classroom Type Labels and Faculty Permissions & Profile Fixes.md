# Classroom Type Labels, Faculty Permissions, Tasks & Profile Fixes

This implementation plan resolves four distinct issues identified across Classroom sync and Faculty account workflows:
1. **Classroom Task Update Summary Modal Type Labels**: The modal currently hardcodes `Added Task` / `Updated` regardless of item type. It will now distinguish and display specific badges/pills for `Announcement`, `Assignment`, and `Materials`.
2. **Faculty Periodic Logout Issue**: On background token refreshes, tab refocus, or page reload, `App.currentLoginRole` defaulted to `'student'`, triggering an erroneous cross-role rejection check in `handleAuthenticatedUser()` that invoked `Auth.logout()`. This will be restricted to explicit interactive login attempts.
3. **Department Notices Permission Error (`cr-notice.js:155`)**: The Firestore query `db.collection('cr_notices').where('department', '==', userDept)` fails security rules for non-admin/unapproved users because it attempts to query class notices alongside department notices. Restricting department notice queries to `isDepartmentNotice == true` satisfies Firestore security rules.
4. **Faculty Preview Mode Tasks & Profile Button Null Text**:
   - `DB.getFacultyTasks` strictly queried `.where('semester', '==', null).where('section', '==', null)`, failing to retrieve tasks if fields were omitted/undefined or if tasks had `addedByRole === 'Faculty'` created in preview mode.
   - When Admin entered Faculty Preview mode, `DB.createTask` attributed tasks to `'Admin'` instead of `'Faculty'`, and Classroom sync captured the Admin's semester/section instead of `null`.
   - The navbar profile button card (`#user-department`) formatted department, semester, and section without filtering out `null`, displaying `CSE • null • null`. Filtering out `null`/empty values will ensure clean display like `CSE`.
