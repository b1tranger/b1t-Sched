# Implementation Plan - User Role Display & Admin Role Preview Mode

Display the current user's role beneath the Student ID in Profile Settings ([js/profile.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/profile.js)), provide an interactive "Preview as" dropdown exclusively for Admins to simulate other user roles (Faculty, CR, Student, Blocked) in temporary session storage, display `(preview)` beside simulated roles, and add an accessible "Exit Preview" banner and button.

## User Review Required

> [!IMPORTANT]
> **Exit Preview UI Placement Proposal**:
> 1. **Floating Global Banner (Top-Center)**: A sleek, modern floating pill (`#admin-preview-banner`) at the top of the viewport (`👁️ Previewing as: Faculty | [Exit Preview]`). It stays visible across all pages (Dashboard, Classroom, Profile, Timeline, Calendar, etc.) so the admin always has immediate context and single-click exit anywhere.
> 2. **Profile Settings Dedicated Control**: An "Exit Preview" button and reset option directly next to the "Preview as" dropdown in Profile Settings.
> 3. **Homepage User Card Indicator**: An amber preview tag shown in the home profile card on the dashboard.
> 
> *We propose enabling both the Floating Global Banner and the Profile Settings controls for maximum clarity and ease of use.*

### Logic & State Management

#### [MODIFY] [js/app.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/app.js)
- Track `this.realRoles` (the actual authenticated roles from Firestore) alongside the active UI roles (`this.isAdmin`, `this.isCR`, `this.isFaculty`, `this.isBlocked`).
- Implement `this.previewRole` reading from `sessionStorage.getItem('b1t_admin_preview_role')`.
- Add helper methods `App.setPreviewRole(role)` and `App.exitPreview()`:
  - Updates `sessionStorage` (cleared automatically when browser session closes).
  - Recalculates and applies active UI role flags (`UI.toggleAdminControls`, `UI.toggleBlockedUserMode`, `App.loadDashboardData()`).
  - Updates the preview banner and Profile Settings UI.
- Wire event listeners for the exit preview buttons and preview dropdown.

#### [MODIFY] [js/profile.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/profile.js)
- In `loadProfile()`:
  - Determine and display the active user role (Admin, Faculty, CR, Student, Blocked) under `#profile-student-id`.
  - If preview mode is active, append `(preview)` to the role display.
  - If the real user is Admin (`App.realRoles?.isAdmin`), reveal the "Preview as" dropdown populated with options (`Admin (Default)`, `Faculty`, `CR`, `Student`, `Blocked`).
  - Handle dropdown `change` event to call `App.setPreviewRole(selectedRole)`.

#### [MODIFY] [js/ui.js](file:///d:/GitHub/[oU1TS]/b1t-Sched/js/ui.js)
- Add `UI.updatePreviewBanner(isPreview, previewRole)` to manage display of the floating preview banner and preview tags.

## Verification Plan

### Manual Verification
1. **Regular User Role Display**:
   - Sign in as regular student: Verify "Role: Student" displays under Student ID without any "Preview as" dropdown.
   - Sign in as CR/Faculty: Verify "Role: CR" or "Role: Faculty" displays with appropriate role styling.
2. **Admin "Preview as" Dropdown & Simulation**:
   - Sign in as Admin: Verify "Role: Admin" displays under Student ID along with the "Preview as:" dropdown.
   - Select "Faculty": Verify app enters Faculty preview mode, role shows "Faculty (preview)", admin controls adjust to Faculty mode, and top floating `#admin-preview-banner` appears.
   - Select "CR": Verify role updates to "CR (preview)" and CR controls appear.
   - Select "Student": Verify role updates to "Student (preview)" and admin/CR controls hide.
   - Select "Blocked": Verify role updates to "Blocked (preview)" and restricted banner/mode triggers.
3. **Exit Preview & Session Reset**:
   - Click "Exit Preview" on the floating banner: Verify preview mode immediately ends, admin view restores, banner disappears, and role shows "Admin".
   - Start preview mode and reload page: Verify preview persists in current tab via `sessionStorage`.
   - Clear session/open in new tab: Verify preview resets to default Admin.
