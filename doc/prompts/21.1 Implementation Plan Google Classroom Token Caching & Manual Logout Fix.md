# Implementation Plan: Google Classroom Token Caching & Manual Logout Fix

Fix frequent user sign-ins caused by premature token deletion and implement comprehensive manual logout functionality across Google Classroom integration components.

## Problem Context
1. **Frequent Sign-In / Logged Out Issue**:
   - Google OAuth access tokens expire after 1 hour (3600s).
   - Previously, `checkPersistedSession()` in `js/classroom.js` checked `token_expiry`. Whenever the token expired or when silent refresh failed with `interaction_required`, the code executed `localStorage.removeItem('classroom_connected')`, `localStorage.removeItem('classroom_token')`, and `localStorage.removeItem('classroom_token_expiry')`.
   - Wiping `classroom_connected` from `localStorage` treated expired 1-hour access tokens as a full user disconnection, forcing users to repeatedly sign in from scratch every hour or upon returning to the site.
2. **Missing Manual Logout Function**:
   - `Classroom.logout()` existed as a JS method, but was only rendered in the "My Classes" view and empty course list view.
   - Users viewing "All Courses" (To-Do / Notices), viewing individual course details, or opening the Desktop Modal / Mobile Sidebar headers had no visible or consistent "Sign Out" / "Disconnect" button.

## User Review Required

> [!IMPORTANT]
> **Token Persistence Strategy**: `classroom_connected = 'true'` will be preserved across page reloads and 1-hour token expirations. The user will remain "Connected" to Google Classroom. If token renewal via silent GIS request (`prompt: 'none'`) is blocked by browser 3rd-party cookie policies, cached data will be served with a 1-click "Reconnect" option instead of logging out the user.

> [!NOTE]
> **Manual Logout**: Explicitly clicking "Sign Out" will revoke the OAuth access token, clear `localStorage` connection flags, purge cached Classroom data, and reset the view to the Google Sign-In prompt.

### Google Classroom Module

#### [MODIFY] [js/classroom.js](file:///c:/Users/.../Documents/GitHub/%5BoU1TS%5D/b1t-Sched/js/classroom.js)
- Update `checkPersistedSession()`:
  - Preserve `classroom_connected` flag in `localStorage` when token expires.
  - Attempt silent token refresh (`this.tokenClient.requestAccessToken({ prompt: 'none' })`) when `classroom_connected` is true but token is expired or missing.
  - If silent refresh succeeds, save new token and updated expiry.
  - If silent refresh fails with `interaction_required` or timeout, flag `hasExpiredSession = true` and serve cached data via `showCachedDataWithBanner()`, while keeping `classroom_connected = 'true'`.
- Update `_handleAuthError(error)`:
  - Do NOT purge `classroom_connected` from `localStorage` on benign `interaction_required` errors.
- Update `logout()` & `cleanupSession()`:
  - Explicitly revoke token, clear `classroom_connected`, `classroom_token`, `classroom_token_expiry`, clear `CacheManager` classroom data, reset module state, and render login screen.
- Update UI Renderers (`renderAllItems`, `renderCourseDetails`, `renderCourseList`, `renderExpiredSessionBanner`):
  - Add consistent "Sign Out" button in all view headers.
- Update `openClassroomParams()`:
  - Seamlessly attempt silent token refresh if `classroom_connected === 'true'` and token is expired when opening Classroom window.
